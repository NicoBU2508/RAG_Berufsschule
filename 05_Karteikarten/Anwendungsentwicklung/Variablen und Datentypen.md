<!-- card-id: variablen-und-datentypen-01 | typ: abgrenzung | pruefung: AP1/AP2 -->
**Worin unterscheiden sich Deklaration und Initialisierung einer Variable in Java, und welche Compiler-Regel gilt beim Auslesen?**
?
**Deklaration** erstellt die Variable mit Datentyp und Bezeichner (`int x;`), **Initialisierung** weist den ersten Wert zu (`x = 5;`). Prüfungsfalle: Eine Variable darf erst ausgelesen werden, nachdem sie initialisiert wurde – sonst ist der Code nicht kompilierbar.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 20–21](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=20>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-02 | typ: abgrenzung | pruefung: AP1/AP2 -->
**Wie unterscheiden sich Instanzvariablen, Klassenvariablen und lokale Variablen in Java?**
?
**Instanzvariablen** stehen jeweils einem konkreten Objekt für individuelle Werte zur Verfügung. **Klassenvariablen** sind für alle Objekte gemeinsam verfügbar (z. B. laufende Nummer). **Lokale Variablen** existieren nur innerhalb des Codeblocks bzw. der Methode, in der sie deklariert wurden.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 19](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=19>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-03 | typ: definition | pruefung: AP1/AP2 -->
**Welche 8 primitiven Datentypen hat Java (mit Bitgröße) und wie grenzt sich `String` davon ab?**
?
Primitive Datentypen: `boolean` (1 Bit), `byte` (8 Bit), `short` (16 Bit), `char` (16 Bit), `int` (32 Bit), `float` (32 Bit), `long` (64 Bit), `double` (64 Bit). `String` hingegen ist ein **komplexer Datentyp** (Klasse), der Zeichenketten aus mehreren Elementen abbildet.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 26–27](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=26>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-04 | typ: pruefungsfalle | pruefung: AP1/AP2 -->
**Welches Ergebnis liefert `first + second` bei `String` (`"5"`) im Vergleich zu `int` (`5`) in Java?**
?
Bei `String` (`"5" + "5"`) erfolgt eine Zeichenkettenverkettung (**Konkatenation**), das Ergebnis ist `"55"`. Bei `int` (`5 + 5`) wird eine mathematische **Addition** ausgeführt, das Ergebnis ist `10`.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 28](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=28>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-05 | typ: anwendung | pruefung: AP1/AP2 -->
**Wann nutzt Java eine implizite bzw. explizite Typkonversion (Type Cast) und was ergibt `int num = (int) 3.57;`?**
?
Eine **implizite Typkonversion** erfolgt automatisch bei kompatiblen, größeren Zieltypen (z. B. `int` in `double`). Bei Verkleinerung ist ein **expliziter Type Cast** nötig: `(int) 3.57` weist `num` den Wert `3` zu – die Nachkommastellen entfallen.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 29–30](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=29>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-06 | typ: pruefungsfalle | pruefung: AP1/AP2 -->
**Wie unterscheidet sich die Variablenerstellung in Python von Java, und warum braucht `input()` in Python oft ein Casting?**
?
In **Python** müssen Variablen nicht vorab deklariert werden, sondern entstehen automatisch bei der ersten Wertzuweisung. Da `input()` immer eine Zeichenkette (`str`) zurückgibt, müssen eingelesene Zahlen vor Berechnungen explizit konvertiert werden (z. B. `int(input())`).
*Quelle: AE Anwendungsentwicklung (2. LJ) · [Mitschrift_AE_Eix.pdf · S. 14, 16](<99_Originale/Berufsschule/AE/2_LJ/AE_Eix/Mitschrift_AE_Eix.pdf#page=14>) (von 26) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/AE_2LJ_Eix_Mitschrift|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-07 | typ: code_trace | pruefung: AP1/AP2 -->
**Welchen Wert hat `erg` in Java nach: `int a = 7; int b = 2; double erg = a / b;`?**
?
**`3.0`**! Da `a` und `b` beide `int` sind, führt Java zuerst eine ganzzahlige Division (`7 / 2 = 3`) aus und wandelt erst danach implizit in `double` (`3.0`) um (für `3.5` wäre `(double) a / b` nötig).
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 29–30](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=29>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*

<!-- card-id: variablen-und-datentypen-08 | typ: code_trace | pruefung: AP1/AP2 -->
**Was passiert beim Kompilieren bzw. Ausführen dieses Java-Codes: `int x; System.out.println(x + 1);`?**
?
**Compiler-Fehler!** Die lokale Variable `x` wurde zwar deklariert, aber **nicht initialisiert** — sie darf in Java vor der ersten Wertzuweisung nicht ausgelesen werden.
*Quelle: AE Anwendungsentwicklung (1. LJ) · [02_Unternehmenswiki-7.Block.pdf · S. 20–21](<99_Originale/Berufsschule/AE/1_LJ/Stößl/02_Unternehmenswiki-7.Block.pdf#page=20>) (von 71) · [[02_Faecher/AE_Anwendungsentwicklung/Quellen/Stol_02_Unternehmenswiki_7_Block|Quellnotiz]]*
